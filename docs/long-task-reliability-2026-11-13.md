## Подтверждённые ошибки и исправления

- При перезапуске после сбоя опроса терялся ID платной транскрипции. Теперь перед POST сохраняется состояние `submitting`, после ответа — ID. Повторный запуск опрашивает прежний ID; неопределённый результат POST блокирует автоматическую повторную оплату. Сбой сохранения намерения не допускает POST.
- Смена ключа контрольной точки скрывала платное задание и могла заменить его новым. Чтение теперь сначала проверяет task-owned запись независимо от ключа; смена параметров после сохранённой транскрипции/отправки требует восстановить параметры либо явно создать другую задачу.
- Готовая контрольная точка обходила проверку модели. Теперь provenance проверяется до восстановления текста/таймингов: старые данные не записываются в кеш под новой моделью.
- Для загрузок, Twitch и Kick проверялся исходник незавершённого платного задания, но не готовой расшифровки. Новые контрольные точки получают fingerprint для всех источников. Изменённые байты останавливают возобновление до восстановления старых таймингов; прежний прогресс сохраняется.
- Незавершённый FFmpeg оставлял ненулевой MP3, который повторный запуск принимал за готовый. Извлечение теперь публикует результат атомарным переименованием только после успешного завершения.
- Отложенная очередь теряла игровой профиль. Он добавлен в сохраняемые аргументы.
- Ошибка уведомления/метаданных после фиксации завершения могла запустить удаление результата. Постобработка больше не переводит уже завершённую задачу в ветку очистки.
- YouTube topic/series/recap/trailer получали `plan_cache=None`, хотя планировщик требует интерфейс кеша. Интерфейс предоставляется, но чтение и запись неподтверждённых URL-кешей отключены. Финальный план сохраняется в контрольной точке задачи.

## Безопасная практическая проверка длинного видео (НЕ выполнялась)

1. Создать отдельный стенд с собственными PostgreSQL, Redis, медиахранилищем, синтетическим пользователем и лимитами. Никаких рабочих томов/сетей/секретов. Использовать разрешённую владельцем копию видео на 1–2 часа с известными репликами и контрольными временными метками. Сначала отключить исходящие платные запросы, применить заглушку провайдера и анализа.
2. Прервать загрузку и извлечение аудио. После возобновления не должно использоваться частичное MP3; исходник должен проходить проверку продолжительности/размера. Сверить fingerprint на одном и другом worker. Смена представления аудио/полного видео может давать разные байтовые fingerprint — это безопасная остановка, но не доказательство семантической смены ролика.
3. С заглушкой остановить worker после фиксации `submitting`, затем после `submitted`, затем после готового транскрипта. В первом случае повторный POST запрещён до сверки; во втором опрашивается прежний ID; в третьем восстанавливаются текст и слова без повторной транскрипции даже после очистки локального sidecar.
4. Вызвать сбой анализа и загрузки выбранных фрагментов. После возобновления не повторять транскрипцию; после сохранённого анализа не повторять анализ. Финальный план и тайминги неизменны.
5. Прервать рендер после одного готового клипа, возобновить и проверить отсутствие дублей, сохранность прежнего клипа и генерацию только недостающих. Сменить только оформление и проверить повторный рендер без новой транскрипции. Для series/recap/trailer отдельно проверить правила целостности результата.
6. Отменить на загрузке, опросе транскрипции и между клипами. Терминальный статус отмены не должен заменяться завершением; после возобновления сохранённые этапы используются повторно. Отмена не обязана мгновенно прекращать синхронный поток и не отменяет оплату уже принятого провайдером задания.
7. Подменить байты под прежней ссылкой, модель, язык, профиль. Не должно быть смешения старых слов/плана с новым исходником или скрытого нового платного POST. Старые результаты сохранены. Проверить отказ кеша для другого пользователя; межзадачный кеш сейчас предназначен для YouTube, не обещает повторное использование Twitch/Kick/загрузок.
8. Только после отдельного согласования бюджета разрешить ОДНО настоящее задание транскрипции. Записать ID и сверить число заданий/начислений у провайдера; перезапускать после сохранения ID, а не намеренно терять ответ POST. Анализ/повторное планирование также могут стоить денег, как и Apify/прокси, трафик и хранилище. Новая задача после блокировки неопределённой отправки тоже может создать повторный расход — сначала сверка у провайдера.

## Ограничения

- План в родительском каталоге не удалось прочитать: файловый инструмент ответил `Path outside workspace`. Отказ не обходился. Соответствие его точным формулировкам не подтверждено.
- Нет полного испытания живой очереди, аварийного завершения ОС, двух worker, реальной БД контрольных точек, реального SDK по сети или рендера длинного видео. Прежняя проверка JSONB-кеша на PostgreSQL 15 не повторялась и не заменяет эти проверки.
- Старые контрольные точки без fingerprint/provenance сохраняют прежнюю совместимость: доказать их идентичность задним числом нельзя. Старые уже отправленные задания без сохранённого ID автоматически восстановить нельзя.
- При неоднозначном POST требуется ручная сверка; автоматического поиска задания у провайдера/экрана разрешения неопределённости нет. Прямой вызов низкоуровневой транскрипции без task-checkpoint не получает эту гарантию.
- Сохранение checkpoint из синхронного потока ждёт БД без отдельного таймаута. Зависание БД и длительность отмены требуют практической проверки; подтверждённого взаимного ожидания потоков не найдено.
- Безопасный отказ при изменении настроек намеренно консервативен: восстановить исходные настройки или явно создать новую задачу, а не молча повторять платную работу.
- Старая временная PostgreSQL-проверка из предыдущей задачи сюда не подключалась; её ресурсы не трогались. Коммитов, push и развёртывания не было.
